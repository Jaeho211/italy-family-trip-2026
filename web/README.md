# ITALIA — 이탈리아 가족여행 메인 사이트

Vite + React + TypeScript 앱을 GitHub Pages **기본 주소** `/italy-family-trip-2026/`에 배포합니다. 이전 MkDocs 여행 수첩과 상세 자료·지도는 **`/italy-family-trip-2026/legacy/`** 아래에 원형 보존합니다. 기존 `/preview/`는 새 기본 주소로 리다이렉트합니다.

## 로컬 개발

저장소 루트에서 먼저:

```bash
python -m pip install -r requirements.txt
mkdocs build --strict
python web/scripts/prepare_preview.py --photos
cd web
npm install
npm run dev
```

`--photos`는 Wikimedia Commons의 **CC0 또는 CC BY 4.0으로 공개된 사진**을 빌드 시 내려받아 로컬 파일로 저장합니다. 웹사이트 방문자 브라우저에서 외부 사진을 핫링크하지 않습니다. 이미 준비된 사진은 재다운로드하지 않습니다.

`prepare_preview.py`는 기존 MkDocs 빌드 결과의 `site/assets/trip-data.json`을 복사하고 `docs/reservations.md`에서 `web/public/data/reservations.json`을 생성하므로 날짜별 일정과 예약 현황을 새 앱에 중복 하드코딩하지 않습니다. Vite 빌드 전에 반드시 실행합니다.

```bash
npm run build
npm run preview
```

## 메인 사이트 범위

- 홈 화면은 **여행 기간·여행 개요 → 전체 날짜별 일정 → 주요 방문지 사진 → 예약·준비 링크** 순서
- 날짜 상세 화면은 **날짜·지역·예약/재확인 상태 → 경로와 개요 → 준비·확인 → 관광지 사진이 포함된 이동·방문 순서 → 세부 근거** 순서
- 전체 11일 날짜 선택과 기존 일정 데이터의 실시간 반영
- 이동·방문 순서에는 사진이 확보된 관광지(포지타노·아말피·라벨로·폼페이·콜로세움·판테온·성베드로 대성당·치비타·트레비 분수·플레비시토 광장)에만 본문 크기의 사진 섹션 표시. 교통·숙소 항목은 텍스트 유지
- 날짜 대표사진은 `web/src/day-photos.json`에 등록된 해당 날짜의 실제 방문·이동 장소로만 선정합니다. 12/23 테르미니역, 12/26 톨레도역, 12/28 나보나 광장, 12/31 스페인 계단, 1/1 트라스테베레 대안 산책, 1/2 포로 로마노. 다른 사진이 있는 방문 순서와 **동일한 장소의 사진은 대표사진으로 중복 사용하지 않습니다.**
- 12/26 산 그레고리오 아르메노 크리스마스 거리, 12/29 바티칸 박물관, 12/30 오르비에토 두오모도 방문 순서에 별도 사진 섹션으로 보완합니다.
- 12월 25일 아말피 해안은 포지타노·아말피·라벨로(선택) 사진을 일정 항목에 배치하고, 중복된 하단 사진 카드 대신 기존 지도 링크를 활용
- `/#/reservations`는 React 기본 디자인과 통합된 예약 현황이며 `docs/reservations.md`의 완료·예매 예정·제외·재확인 항목을 빌드 시 변환합니다. 예약 상태는 원문을 그대로 유지하며 별도 복제하지 않습니다.
- `/#/map`은 React 메인 디자인과 통합된 여행 지도이며 기존 `trip-data.json`의 장소 좌표를 사용합니다. 지역별 필터와 `/#/map/YYYY-MM-DD` 날짜별 필터(지역 간 이동·숙소 포함), 장소 목록, Google Maps 연결을 제공합니다. MapLibre GL JS 5.24.0과 OpenFreeMap Positron 스타일을 사용합니다. 배경 타일은 온라인 연결이 필요합니다.
- 이전 MkDocs 페이지·지도·예약·가이드·오프라인 워커는 `/legacy/`로 이동하되 원본 소스는 유지
- 기존 `/itinerary/`, `/map/` 등 링크는 `/legacy/`로 리다이렉트하고, 이전 직접 지도 링크 `/assets/map/`도 유지
- React 메인 페이지는 별도 PWA manifest/서비스 워커를 등록해 **설치·기본 화면·11일 일정·사진 오프라인 재열기**를 지원합니다. 이전 MkDocs 서비스 워커는 `/legacy/` 범위에서 독립 동작합니다

## PWA 설치와 업데이트

- Android Chrome 등 PWA 설치 프롬프트를 제공하는 브라우저에서는 헤더의 **앱 설치**를 누르면 설치 확인창을 표시합니다.
- 프롬프트가 제공되지 않으면 헤더의 **앱 설치**를 누를 때 브라우저별 설치 안내가 표시됩니다. Android는 브라우저 메뉴의 **앱 설치 / 홈 화면에 추가**, iOS Safari는 **공유 → 홈 화면에 추가**를 사용합니다.
- 이미 설치된 앱의 독립 실행창에서는 설치 버튼을 숨깁니다.
- 배포된 React 앱은 `/sw.js` 서비스 워커로 페이지 셸, 빌드 시 해시된 JS/CSS, `data/trip-data.json`, `data/reservations.json`, 로컬 사진, 앱 아이콘을 첫 설치 시 캐시에 저장합니다.
- 네트워크 연결이 되면 HTML과 여행 일정 데이터를 우선 갱신하고, 연결이 끊기면 캐시된 데이터로 표시합니다. 외부 Google Maps·지도 타일·예약처 링크까지 오프라인 지원하는 것은 아닙니다.
- 새 버전의 워커가 대기 중이면 헤더에 **업데이트**를 표시합니다. 누르면 새 버전을 활성화하고 페이지를 다시 읽습니다.
- 기존 `/legacy/`의 앱·캐시는 새 React 앱과 별도로 관리합니다. 예전 루트 워커 캐시(`italy-journey-*`)는 임의로 삭제하지 않습니다.
- 사용자에게 오프라인 사용 가능 여부를 안내할 때는 **설치 완료 후 온라인에서 한 번 열고 캐시가 저장된 다음**이라는 전제를 명시합니다.

`web/public/sw.js`는 템플릿입니다. `web/scripts/publish_site.py`가 실제 Vite 빌드 파일 목록과 해시를 넣어 `site/sw.js`를 생성하며, 설치 조건에 필요한 192/512px PNG 아이콘은 기존 MkDocs 정적 자산을 재사용합니다.

## 콘텐츠·타이포그래피 원칙

1. 제목은 장소·날짜·활동을 설명한다. 감성적인 문장, 시적인 카피, 영어 장식용 제목은 사용하지 않는다.
2. 당일 예약 상태와 재확인 사항, 이동 순서를 사진 소개보다 먼저 찾을 수 있어야 한다.
3. 제목 30~44px, 섹션 제목 23~28px, 본문 16px, 보조 정보 14~15px를 기본으로 한다. 모바일 최소 보조 글씨 13px를 유지한다.
4. 사진은 장소 확인과 방문 동기 제공을 위한 보조 정보다. 여행지와 다른 사진을 해당 날짜의 특정 명소처럼 사용하지 않는다.
5. 일정·예약·운영시간을 별도 프런트엔드 코드에 복제하지 않고 `trip-data.json`과 기존 문서에서 가져온다.

## 방문 순서 사진 구성

`web/src/place-photos.json`이 기존 장소 ID(`docs/assets/map/places.geojson`의 `sort`)와 `web/scripts/prepare_preview.py`에서 내려받는 사진 키를 연결합니다. 장소 ID를 독립 방문 항목으로 표시할 수 없는 날짜의 개요 사진은 `web/src/day-photos.json`에서 날짜·방문 장소 기준으로 별도 관리합니다.

- 관광지 항목은 번호 → 장소명 → 원본 방문 계획 → **넓은 가로 사진** → 지도 링크 순서로 자연스럽게 연결합니다. 사진을 위한 별도 갤러리·썸네일·카드형 패널을 사용하지 않습니다.
- 렌터카 수령·기차 이동·숙소 체크인 등 사진이 필요 없는 단계는 기존의 번호형 목록을 유지합니다. 여러 장소가 섞인 항목에도 무관한 사진을 넣지 않습니다.
- PC에서는 방문 계획 아래에 **본문 폭 전체의 16:9 사진**(최대 높이 600px)을 표시하고, 모바일에서는 **16:10 사진**을 표시합니다. 본문 글자 크기는 16px로 유지합니다.
- 사진의 채도·대비·밝기를 CSS로 동일하게 조정하여 주변 정보 페이지의 차분한 색감과 조화되도록 합니다.
- **사진은 클릭할 수 없고 확대 기능도 없습니다.** 지도 링크는 기존대로 사용할 수 있습니다.
- 같은 장소가 여러 번 등장하면 **최종 단일 장소 방문 항목**에만 사진이 나옵니다(콜로세움 택시 이동과 실제 입장 중 실제 입장에만 표시).
- 날짜 개요는 방문 순서에 등장하는 대형 사진과 **서로 다른 실제 방문 장소**를 사용합니다. 같은 장소를 대표사진과 방문 순서 사진으로 두 번 사용하지 않도록 빌드에서 확인합니다.
- 빌드 준비 단계에서 장소 ID, 사진 키, 설명 텍스트, 방문 항목 존재 여부를 검사합니다.
- **새 사진을 추가할 때**는 출처·라이선스를 확인한 뒤 `PHOTO_CREDITS.md`, `prepare_preview.py`, `place-photos.json` 또는 `day-photos.json`을 함께 갱신합니다.

## 사진과 저작권

`scripts/prepare_preview.py`의 `PHOTOS`에 명시한 Wikimedia Commons 파일만 내려받습니다. 기존 파일과 신규 파일의 대부분은 CC0이며, 치비타 항공 전경은 CC BY 4.0으로 저작자·원본·라이선스·표시 변형 사항을 `PHOTO_CREDITS.md`에 명시합니다. 출처와 사진별 원저작자는 앱 하단의 사진 출처와 `PHOTO_CREDITS.md`를 참고합니다. 사진은 실제 여행 시기의 날씨를 보장하지 않습니다.

## 배포 동작과 확인 절차

GitHub Actions는 `mkdocs build --strict`로 원본 여행 데이터와 기존 사이트를 만들고, `web/scripts/prepare_preview.py --photos`로 사진과 `trip-data.json`을 준비한 후 React를 빌드합니다. 마지막에 `web/scripts/publish_site.py`가 기존 MkDocs 사이트를 `site/legacy/`로 옮기고 React 빌드 결과를 `site/` 루트에 배치합니다.

배포 시 아래 경로를 확인해야 합니다.

- `/`: React 메인 페이지와 11일 일정 데이터
- `/#/day/2026-12-25`: 아말피 여행일 상세
- `/#/reservations`: React 예약 현황(완료·예매·제외·재확인)
- `/#/map`: React 여행 지도(전체 지역·전체 날짜)
- `/#/map/2026-12-24`: React 여행 지도(12/24 나폴리 이동일)
- `/legacy/`: 이전 MkDocs 홈
- `/legacy/?view=map&date=2026-12-25`: 기존 지도 앱
- `/legacy/reservations/`: 원본 예약 현황
- `/map/`, `/itinerary/`, `/preview/`: 과거 주소 호환 리다이렉트

기존 여행 일정·예약·운영 정보의 정본은 계속 `docs/`입니다. React 메인 페이지에는 같은 지도 데이터를 이용한 새로운 지도 화면이 있으며, 이전 지도는 `/legacy/`에 보존합니다. React의 설치·오프라인 일정 및 장소 목록 열람은 지원하지만, 외부 배경지도·예약 링크까지 오프라인 지원하지는 않습니다.
