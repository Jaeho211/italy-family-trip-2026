# 앱 이동 UX 설계

검토일: 2026-10-10. 재확인: 배포 후 설치 앱에서 주요 이동 흐름을 확인할 때.

## 확인된 문제

- 방문일 상세 안내가 내부 일정 URL인데도 외부 링크 생성 함수의 `_blank`를 사용했다. 별도 앱 화면을 여는 동작과 뒤로가기 시 종료 현상은 사용자 보고이며 실제 기기 재현은 미확인이다.
- 식당 찾기·확대 지도·귀국일 짐 안내에도 내부 화면을 새 창으로 여는 코드가 있었다.
- 장소 안내창 닫기는 히스토리를 대체해 동일한 일정 화면을 중복 남겼다.
- 문서 진입 시 앱의 popstate 리스너를 해제해, 복원된 앱 DOM에서는 뒤로가기 동작을 잃을 수 있었다.

## 설계 원칙

- 내부 화면은 하나의 앱 흐름으로 이동한다. 새 창은 외부 지도·공식 사이트 등에 한정한다.
- 뒤로가기는 사용자가 직전에 본 화면으로 한 단계 돌아간다. 장소 안내창은 화면 위에 열린 한 단계로 취급하고, 닫기도 그 단계를 되돌린다.
- 날짜·탭·장소 선택은 URL로 복원한다. 식당 찾기의 도시·주변 장소 필터도 URL로 전달한다. 가족 위치 데이터는 이 과정에서 수집·저장하지 않는다.
- 주요 메뉴와 테마는 문서·확대 지도에도 유지한다. 지도 iframe은 부모 화면의 메뉴를 사용한다.
- 방문일 상세 안내의 라벨은 내부 이동 화살표를 사용해 외부 길찾기와 구분한다.

## 주요 검증 흐름

1. 오늘 일정 → 장소 안내 → 방문일 상세 안내 → 뒤로가기: 원래 날짜·탭과 장소 안내로 복귀.
2. 장소 안내 → 닫기: 원래 화면으로 복귀. 뒤로가기에서 중복된 일정 화면을 남기지 않음.
3. 장소 URL을 직접 열기 → 닫기: 방문 경로가 없으면 URL의 장소 선택만 제거해 앱을 종료하지 않음.
4. 오늘 일정 또는 장소 → 주변 식당: 같은 앱의 식당 문서로 이동하고 날짜·도시·주변 기준 전달.
5. 지도 크게 열기: 같은 앱에서 지도 확대, 하단 메뉴 유지. iframe 안에서는 중복 메뉴 없음.
6. 외부 길찾기·공식 안내: 새 화면으로 열고 원래 앱 상태 유지.

## 구현 범위와 실제 기기 확인

- 링크 대상, 장소 히스토리, 문서 복원 이벤트, 식당 조건 전달과 직접 지도 화면의 메뉴를 수정한다.
- Android·iPhone 설치 앱의 실제 복귀·스크롤·외부 앱 전환은 배포 후 확인이 필요하다. 검증 전 실제 기기에서 완료된 것으로 단정하지 않는다.
- 검색어·스크롤 등 추가 상태 보존, 내부 문서에서 이전 화면으로 돌아가는 명시적 버튼은 실제 사용 흐름을 보고 추가 검토한다. 이번 변경은 새 예약·여행 일정 결정을 포함하지 않는다.
